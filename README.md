# SKYWARDEN (Cam to Drone) · v1.1

Κέντρο ελέγχου που ενώνει **κάμερες → ελεγκτή → drone**.
Οι κάμερες κάθε επιχείρησης δίνουν συναγερμό, το κουτί (Raspberry/Linux) τον μεταφράζει και τον στέλνει στον κεντρικό server, και ο ελεγκτής τον χειρίζεται σε μία οθόνη: εικόνα, χάρτης, πρωτόκολλο ενεργειών, αποστολή drone, μεγάφωνο, ειδοποιήσεις.

```
Κάμερες ──(ONVIF / Hikvision / Dahua / push / ρελέ)──► Κουτί (edge agent) ──HTTPS──► Server ──► Οθόνη ελεγκτή (browser)
                                                                                     └──► DJI Dock (προσομοίωση στη v1)
```

## Τι περιέχει

| Φάκελος | Τι είναι |
|---|---|
| `server/` | Κεντρικός server και οθόνη ελεγκτή. Python 3, χωρίς εξωτερικά πακέτα, βάση SQLite. |
| `edge/` | Πρόγραμμα για το κουτί σε κάθε επιχείρηση (Raspberry Pi / Linux), με εγκατάσταση ως υπηρεσία. |
| `postman/` | Έτοιμα αιτήματα για δοκιμές και εντολές. |
| `data/` | Δημιουργείται στην πρώτη εκκίνηση: βάση, εικόνες, `credentials.txt`. |

## Γρήγορη εκκίνηση (Windows)

1. Διπλό κλικ στο `start.bat`, ή:
   ```
   python server\app.py --port 8080
   ```
2. Ανοίγει το `http://localhost:8080/`.
3. Στην πρώτη εκκίνηση φτιάχνονται χρήστες με τυχαίους κωδικούς στο **`data/credentials.txt`**:
   - `admin`: διαχειριστής
   - `operator`: ελεγκτής
   - `pelatis`: πελάτης, βλέπει μόνο τη δική του επιχείρηση
4. Πατήστε **«+ Δοκιμαστικός συναγερμός»** πάνω δεξιά για να δείτε όλη τη ροή χωρίς κάμερες.

Υπάρχουν έτοιμα **δείγματα επίδειξης**: 3 επιχειρήσεις στην Αττική με κάμερες, επαφές και 3 σταθμούς drone (προσομοίωση). Αλλάζουν ή διαγράφονται από τη Διαχείριση.

Για γρήγορη προσομοίωση πτήσης: `set SIM_SPEED=5` πριν την εκκίνηση (5 φορές πιο γρήγορα).

## Linux server / Docker

```
docker build -t cam2drone .
docker run -d -p 8080:8080 -v cam2drone-data:/data --name cam2drone cam2drone
```
Σε παραγωγή, ο server μπαίνει πίσω από reverse proxy με HTTPS (π.χ. Caddy ή Nginx), ώστε τα κουτιά να συνδέονται με `https://`.

## Οθόνη ελεγκτή: όλα σε μία οθόνη
- **Αριστερά, ουρά περιστατικών:** ταξινόμηση κατά προτεραιότητα, χρονόμετρο, φίλτρα (ανοιχτά, υψηλή προτεραιότητα, drone, κλειστά, ανά επιχείρηση), ήχος για νέο συναγερμό.
- **Κέντρο:** εικόνα κάμερας (με όλες τις λήψεις του περιστατικού), οθόνη drone με ενδείξεις (φάση, ύψος, μπαταρία, θέση) και χάρτης με επιχειρήσεις, σταθμούς, ακτίνα κάλυψης και θέση του drone.
- **Δεξιά, περιστατικό:**
  - Ανάληψη, Ψευδής, Αποστολή drone, Παύση κάμερας, Κλείσιμο.
  - Πρωτόκολλο ενεργειών (checklist ανά επιχείρηση).
  - Μεγάφωνο drone: έτοιμα μηνύματα, ελεύθερο κείμενο, και κουμπί που κρατάς πατημένο για να μιλήσεις από το μικρόφωνο.
  - Ειδοποιήσεις: SMS, email, κλήση, αστυνομία 100/112 με έτοιμη περίληψη.
  - Χρονολόγιο και αναφορά για εκτύπωση ή PDF.
- **Κλιμάκωση:** αν δεν γίνει ανάληψη μέσα στον χρόνο που έχει οριστεί για την επιχείρηση, το περιστατικό ανεβαίνει προτεραιότητα και ειδοποιείται ο ελεγκτής.

## Πώς χωρίζονται και φιλτράρονται τα σήματα
- **Ανά οργανισμό:** κάθε κουτί έχει δικό του token. Κάθε επιχείρηση έχει και δικό της webhook URL για κάμερες που στέλνουν απευθείας.
- **Φίλτρα:** ωράριο οπλισμού, επιτρεπτοί τύποι συναγερμού, παύση κάμερας, απενεργοποίηση κάμερας. Όσα φιλτράρονται φαίνονται στη «Καταγραφή σημάτων».
- **Συγχώνευση:** σήματα της ίδιας επιχείρησης μέσα σε 2 λεπτά ενώνονται σε ένα περιστατικό.
- **Τύποι:**

  | Τύπος | Προτεραιότητα |
  |---|---|
  | Άτομο, Όχημα, Είσοδος συναγερμού | υψηλή |
  | Ζώνη, Γραμμή, Παραποίηση, Πρόσωπο | μεσαία |
  | Κίνηση | χαμηλή |
  | Απώλεια εικόνας | τεχνικό |

  Η αναγνώριση ατόμου ή οχήματος γίνεται στην ίδια την κάμερα (π.χ. AcuSense, WizSense). Το σύστημα τη διαβάζει και την αξιοποιεί.

## Κουτί (edge) σε Raspberry Pi / Linux
```
scp -r edge pi@<ip-κουτιού>:~
ssh pi@<ip-κουτιού>
cd edge && sudo ./install.sh
sudo nano /opt/cam2drone-edge/config.json      # server, token, κάμερες
/opt/cam2drone-edge/venv/bin/python /opt/cam2drone-edge/agent.py --discover   # βρίσκει ONVIF κάμερες
sudo systemctl start cam2drone-edge && journalctl -u cam2drone-edge -f
```
- Το **token** του κουτιού το παίρνετε από Διαχείριση → Κουτιά → «Νέο κουτί».
- Τύποι πηγών στο `config.json`:

  | Τύπος | Τι κάνει |
  |---|---|
  | `hikvision` | ISAPI alertStream, και για NVR με `channels` |
  | `dahua` | eventManager |
  | `onvif` | PullPoint, χρειάζεται `onvif-zeep` |
  | `webhook` | η κάμερα στέλνει στο κουτί στη θύρα 8090 |
  | `gpio` | ξηρή επαφή, π.χ. έξοδος πίνακα συναγερμού |

- Τραβάει φωτογραφία από την κάμερα σε κάθε συναγερμό.
- Αν πέσει το internet, κρατά τους συναγερμούς και τους στέλνει όταν επανέλθει.
- Κάθε 30″ στέλνει «είμαι ζωντανό» για κάθε κάμερα.
- Ελέγχει ότι η ώρα του είναι σωστή, γιατί το ONVIF το απαιτεί.
- Κάνει μόνο εξερχόμενες συνδέσεις, άρα δεν ανοίγουν θύρες στο router της επιχείρησης.
- Δοκιμή: `agent.py --config config.json --test` στέλνει έναν δοκιμαστικό συναγερμό για κάθε κάμερα.

## Κουτί σε Windows (laptop / mini PC στο δίκτυο των καμερών)
Ένα αρχείο, `Cam2Drone-Setup.exe`, χωρίς δικαιώματα διαχειριστή:
1. Ο πελάτης το ανοίγει και γράφει τον **κωδικό κουτιού** (Διαχείριση → Κουτιά → «Νέο κουτί»).
2. Βάζει χρήστη/κωδικό καμερών και πατά «Αναζήτηση καμερών». Βρίσκει Hikvision (SADP), ONVIF (WS-Discovery) και ό,τι έχει ανοιχτή θύρα κάμερας (554/8000/37777), αναγνωρίζει μάρκα και καταγραφικά με τα κανάλια τους.
3. «Εγκατάσταση και εκκίνηση»: αντιγράφεται στο `%LOCALAPPDATA%\Cam2Drone`, ξεκινά στο παρασκήνιο και με κάθε σύνδεση στα Windows. Αν ανοιχτεί ξανά, δείχνει την κατάσταση και επιτρέπει αλλαγές ή διακοπή.

Περιέχει το go2rtc (MIT) για **ζωντανό βίντεο σε πραγματικό χρόνο** και το ffmpeg (LGPL) για κλιπ και ήχο (`edge/windows/THIRD_PARTY.txt`). Το αρχείο δεν είναι υπογεγραμμένο: τα Windows δείχνουν «Τα Windows προστάτευσαν τον υπολογιστή σας» → «Περισσότερες πληροφορίες» → «Εκτέλεση». Σε εταιρικούς υπολογιστές μπορεί να μπλοκαριστεί εντελώς. Για παραγωγή χρειάζεται πιστοποιητικό υπογραφής κώδικα.

Κατασκευή (σε Windows): `python -m pip install pyinstaller onvif-zeep` και `python edge/windows/build.py` → `edge/windows/dist/Cam2Drone-Setup.exe`.

**Ενημέρωση από μακριά (από 1.5.0):** το κουμπί «Ενημέρωση» (Διαχείριση → Κουτιά, ή στη σελίδα κουτιών του τεστ) στέλνει στο κουτί το νέο `agent.py` (λίγα KB). Στα Windows αποθηκεύεται στο `%LOCALAPPDATA%\Cam2Drone\agent.py`, το πρόγραμμα το προτιμά από το ενσωματωμένο όταν είναι νεότερο και επανεκκινείται. Αν δεν ξεκινήσει, μετονομάζεται σε `agent.py.bad` και τρέχει το ενσωματωμένο. Το παλιό πρόγραμμα κλείνει μόνο αφού δει το νέο να τρέχει (αρχείο `agent.started`)· αν το νέο δεν ξεκινήσει, το κουτί συνεχίζει με την παλιά έκδοση. Νέο exe χρειάζεται μόνο για αλλαγές στο ίδιο το setup, στο go2rtc ή στο ffmpeg. **Έλεγχος συνδέσεων βίντεο (από 1.5.9):** οι κάμερες επιτρέπουν περιορισμένο αριθμό συνδέσεων βίντεο και άλλα προγράμματα της επιχείρησης μπορεί να τις πιάνουν όλες (σφάλμα «453 Not Enough Bandwidth»). Το κουτί μιλά πάντα απευθείας με τις κάμερες, πιάνει το πολύ μία σύνδεση ανά κάμερα και: (α) το setup δοκιμάζει τη σύνδεση βίντεο όταν προστίθεται κάμερα και γράφει ποιες διευθύνσεις κρατούν τις συνδέσεις, (β) κάθε 10′ (`video_check_minutes`) το κουτί ξαναελέγχει και, αν μια κάμερα αρνείται, η κονσόλα ανοίγει τεχνικό περιστατικό με την αιτία· όταν επανέλθει, γράφεται στο χρονολόγιο. Συναγερμοί και εικόνα ανά δευτερόλεπτο δεν επηρεάζονται. **Διάγνωση (από 1.5.6):** στη σελίδα κουτιών του τεστ, το κουμπί «Διάγνωση» ζητά από το κουτί να δοκιμάσει κάθε ροή της κάμερας (sub, main, third) και δείχνει αν ανοίγει, με τι κωδικοποίηση, ή με ποιο σφάλμα αρνείται η κάμερα. Η σελίδα τεστ παίρνει τον κώδικα από `testpad/build.mjs` (`node build.mjs` πριν το deploy).

**Ζωντανό βίντεο μέσω κουτιού (go2rtc), χωρίς media server:** όταν το κουτί έχει go2rtc (στα Windows ενσωματωμένο, σε Linux αρκεί το `go2rtc` στο PATH ή δίπλα στο `agent.py`), το «Ζωντανά» της κονσόλας ανοίγει σύνδεση WebRTC: η πρόταση του browser πηγαίνει στο κουτί ως εντολή κάμερας και η απάντηση επιστρέφει από τον ίδιο δρόμο, ενώ το βίντεο πάει απευθείας κουτί → browser (STUN), με καθυστέρηση κάτω από 1″. Χρησιμοποιείται το sub-stream της κάμερας. Αν η κάμερα στέλνει H.265, το ffmpeg το μετατρέπει σε H.264. Αν δεν γίνει απευθείας σύνδεση (π.χ. αυστηρό NAT), η κονσόλα γυρίζει σε ~1 καρέ/δευτ.

## Κάμερες χωρίς κουτί (απευθείας webhook)
Από Διαχείριση → Οργανισμοί, αντιγράψτε το «Webhook για κάμερες» της επιχείρησης.
Για Hikvision: Configuration → Network → Advanced → **HTTP Listening** (IP/θύρα του server, URL `/webhook/<token>`), και στο event **Linkage → Notify Surveillance Center**.

## Ειδοποιήσεις
Διαχείριση → Ειδοποιήσεις:
- **SMS:** μέσω HTTP API παρόχου (URL, headers, σώμα JSON με `{to}`, `{text}`, `{sender}`). Στην Ελλάδα το όνομα αποστολέα θέλει προεγγραφή στον πάροχο.
- **Email:** μέσω SMTP.
- Χωρίς ρυθμισμένο πάροχο, οι ειδοποιήσεις **καταγράφονται ως προσομοίωση** και δεν στέλνονται.
- Κλήσεις και αστυνομία: τις κάνει ο ελεγκτής από τηλέφωνο, και το σύστημα δίνει τον αριθμό, την έτοιμη περίληψη και καταγράφει το αποτέλεσμα.

## Drone
Στη v1 οι σταθμοί είναι **προσομοίωση**: απογείωση, πορεία, άφιξη, επιστροφή, μπαταρία, προβολέας, κάμερες, μεγάφωνο.
Η σύνδεση με πραγματικό **DJI Dock 3** γίνεται μέσω **DJI Cloud API**, στην κλάση `DjiCloudAdapter` στο `server/logic.py`. Εκεί είναι γραμμένη η αντιστοίχιση κάθε λειτουργίας:

| Λειτουργία | Εντολή DJI Cloud API |
|---|---|
| Πτήση στο σημείο | `fly_to_point` / wayline |
| Επιστροφή | `return_home` |
| Μεγάφωνο | `drc_speaker_tts_play_start` και ζωντανή μετάδοση (AS1) |
| Προβολέας | AL1 |
| Live εικόνα | `live_start_push` |

Χρειάζεται πραγματικό Dock και λογαριασμός DJI developer.

## API για Postman
- Εισάγετε το `postman/Cam-to-Drone.postman_collection.json` και βάλτε στη μεταβλητή `api_token` το token από το `data/credentials.txt`.
- Header: `Authorization: Bearer <api_token>`.
- Εντολές (`POST /api/command`): `ping`, `demo_alarm`, `ack`, `dispatch_drone`, `speaker`, `light_on`, `light_off`, `return_home`, `note`, `false_alarm`, `close`.
- Χωρίς `incident_id`, η εντολή πάει στο πιο επείγον ανοιχτό περιστατικό.

## Νέα στην έκδοση 1.1
- **Βάρδιες:** έναρξη και τέλος βάρδιας από το κουμπί πάνω δεξιά, με σημείωμα παράδοσης για τον επόμενο. Ανάθεση περιστατικού σε ελεγκτή που είναι σε βάρδια, και φίλτρο «Δικά μου».
- **Αναφορές:** περιστατικά, ψευδείς συναγερμοί, χρόνοι ανάληψης και άφιξης drone, ανά ημέρα, ώρα, τύπο, επιχείρηση και ελεγκτή. Λήψη CSV και εκτύπωση. Ο πελάτης βλέπει μόνο τα δικά του.
- **Έλεγχος πριν την πτήση:** τρέχων καιρός στο σημείο (Open-Meteo: άνεμος, ριπές, βροχή, θερμοκρασία, καταιγίδα) και **ζώνες απαγόρευσης** (Διαχείριση → Ζώνες πτήσης). Αν ο έλεγχος αποτύχει, μόνο επόπτης ή διαχειριστής μπορεί να στείλει το drone, με αιτιολογία που καταγράφεται. Τα όρια ρυθμίζονται στο Διαχείριση → Ειδοποιήσεις. Οι ζώνες που υπάρχουν είναι **παραδείγματα**: βάλτε τις επίσημες ζώνες της ΥΠΑ.
- **Πελάτες στο κινητό:** απλή οθόνη για τον πελάτη (κατάσταση, συναγερμοί, εικόνες, κλιπ, ζωντανή εικόνα, αναφορά) που εγκαθίσταται ως εφαρμογή (PWA).
- **Ειδοποιήσεις push** στο κινητό ή τον υπολογιστή (μενού χρήστη → «Ειδοποιήσεις σε αυτή τη συσκευή»): νέος συναγερμός, κλιμάκωση, άφιξη drone, κλείσιμο. Στο iPhone χρειάζεται πρώτα «Προσθήκη στην οθόνη Αφετηρίας». Ο Python server θέλει `pip install cryptography` (το Docker image το έχει).
- **Κλιπ βίντεο:** το κουτί κρατά συνεχώς τα τελευταία δευτερόλεπτα κάθε κάμερας (ffmpeg, χωρίς επανακωδικοποίηση, στη RAM) και στέλνει κλιπ 20″: από 10″ πριν έως 10″ μετά τον συναγερμό. Ρύθμιση `clips` στο `config.json`. Στο Cloudflare τα κλιπ αποθηκεύονται στο R2.
- **Ζωντανή εικόνα:** κουμπί «Ζωντανά» στην κάμερα του περιστατικού. Το κουτί στέλνει περίπου ένα καρέ το δευτερόλεπτο όσο κάποιος βλέπει. Όσο υπάρχει ανοιχτό περιστατικό, το κουτί επικοινωνεί κάθε 2″ αντί για 30″.
- **Ζωντανό βίντεο με ήχο (έτοιμο, ανενεργό μέχρι να υπάρξει media server):** στη Διαχείριση → Ειδοποιήσεις → «Ζωντανό βίντεο με ήχο» μπαίνει η διεύθυνση ενός media server (π.χ. MediaMTX). Τότε, όσο κάποιος βλέπει «Ζωντανά», το κουτί στέλνει εκεί βίντεο (H.264 όπως έρχεται) και ήχο της κάμερας (σε Opus ή AAC), και ο browser το παίζει με WebRTC, καθυστέρηση περίπου 1″. Το ίδιο για την κάμερα του drone όταν συνδεθεί πραγματικό Dock (το Dock στέλνει στον ίδιο server). Χωρίς server: μία εικόνα ανά δευτερόλεπτο. Χρησιμοποιήστε το sub-stream H.264 της κάμερας (το H.265 δεν παίζει σε WebRTC).
- **Αναβολή αποστολής drone:** στο παράθυρο αποστολής, αν το drone δεν μπορεί να πετάξει (καιρός, ζώνη, βλάβη), «Αναβολή αποστολής» με αιτία που γράφεται στο χρονολόγιο, στην αναφορά και στο ιστορικό ενεργειών.
- **Οπλισμός και έλεγχος κάμερας από την κονσόλα** (κουμπί «Έλεγχος ⚙» στο περιστατικό, δίπλα στο «Ζωντανά», ή στη Διαχείριση → Κάμερες):
  - **Οπλισμός ανά κάμερα:** «Όπως η επιχείρηση», «Οπλισμένη» (συναγερμός και εκτός ωραρίου) ή «Αφοπλισμένη» (τα σήματα καταγράφονται, χωρίς συναγερμό).
  - **ONVIF μέσω του κουτιού:** κίνηση PTZ και ζουμ, αρχική θέση, μετάβαση και αποθήκευση θέσεων, έξοδοι της κάμερας (σειρήνα, φως), ημέρα/νύχτα, επανεκκίνηση (μόνο επόπτης/διαχειριστής). Το κουτί διαβάζει τι υποστηρίζει κάθε κάμερα και η κονσόλα δείχνει μόνο αυτά.
  - Ισχύει για κάμερες `"kind": "onvif"`, ή για Hikvision/Dahua με `"onvif": true` στο `config.json` (και `"onvif_port"` αν διαφέρει). Ονόματα εξόδων με `"relay_names"`.
  - Οι εντολές φτάνουν στην κάμερα σε έως 10″ (2″ όσο υπάρχει ανοιχτό περιστατικό ή γίνεται χειρισμός) και καταγράφονται στο ιστορικό ενεργειών και, αν δόθηκαν από περιστατικό, στο χρονολόγιό του.
- **Ενημέρωση κουτιών από μακριά:** το κουτί κατεβάζει μόνο του τη νέα έκδοση από τον server, ελέγχει hash και ότι ξεκινά, και επανεκκινείται (`auto_update` στο config). Από τη Διαχείριση → Κουτιά υπάρχει και κουμπί «Ενημέρωση».

## Νέα στην έκδοση 1.4
- **Έλεγχοι κάθε λεπτό, ακόμα κι αν δεν είναι κανείς συνδεδεμένος:** ένα μικρό Cloudflare Worker (`cloudflare/cron`) τρέχει κάθε λεπτό: κλιμάκωση περιστατικών χωρίς ανάληψη, πορεία drone, κουτιά που σταμάτησαν να επικοινωνούν, διαγραφή παλιών εικόνων.
- **Τεχνικός συναγερμός:** αν ένα κουτί δεν επικοινωνήσει για 3 λεπτά (ρεύμα, internet) ή μια κάμερα δεν απαντά στο κουτί, ανοίγει περιστατικό «Εκτός σύνδεσης» με ειδοποίηση. Όταν επανέλθουν, γράφεται στο χρονολόγιο.
- **Κονσόλα σε καρτέλα στο παρασκήνιο:** συνεχίζει να ελέγχει κάθε 10″, παίζει ήχο και αναβοσβήνει ο τίτλος της καρτέλας.
- **Επαλήθευση 2 βημάτων** (μενού χρήστη) με εφαρμογή στο κινητό, και **κλείδωμα λογαριασμού** για 15′ μετά από 5 λάθος κωδικούς (ξεκλείδωμα από τον διαχειριστή).
- **Διατήρηση δεδομένων (GDPR):** εικόνες, κλιπ και φωνητικά διαγράφονται αυτόματα μετά από Χ ημέρες (Διαχείριση → Ειδοποιήσεις, προεπιλογή 30).
- **Ζώνες πτήσης ως πολύγωνα** και **εισαγωγή αρχείου** ED-269 / GeoJSON / KML (Διαχείριση → Ζώνες πτήσης). Ο επίσημος χάρτης της ΥΠΑ ([Drone Aware GR](https://dagr.hasp.gov.gr/)) δεν δίνει αρχείο· ζητήστε το από την ΥΠΑ.
- **Αναλυτική αναφορά περιστατικού:** χρόνοι, όλα τα σήματα, πρωτόκολλο, πτήσεις drone με καιρό και αναβολές, ειδοποιήσεις, όλες οι εικόνες, χρονολόγιο, υπογραφές.

### Αναβάθμιση της βάσης στο Cloudflare
```
cd cloudflare
npx wrangler r2 bucket create cam2drone-media
npx wrangler d1 execute cam2drone --remote --file migrations/0002_v1_1.sql
npx wrangler d1 execute cam2drone --remote --file migrations/0003_camera_control.sql
npx wrangler d1 execute cam2drone --remote --file migrations/0004_reliability_security.sql
npx wrangler deploy -c cron/wrangler.toml   # ο έλεγχος κάθε λεπτό
npm run deploy
```

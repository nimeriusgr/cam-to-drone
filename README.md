# Cam to Drone · v1

Κέντρο ελέγχου που ενώνει **κάμερες → ελεγκτή → drone**.
Οι κάμερες κάθε επιχείρησης δίνουν συναγερμό, το κουτί (Raspberry/Linux) τον μεταφράζει και τον στέλνει στον κεντρικό server, και ο ελεγκτής τον χειρίζεται σε μία οθόνη: εικόνα, χάρτης, σχέδιο ενεργειών, αποστολή drone, μεγάφωνο, ειδοποιήσεις.

```
Κάμερες ──(ONVIF / Hikvision / Dahua / push / ρελέ)──► Κουτί (edge agent) ──HTTPS──► Server ──► Οθόνη ελεγκτή (browser)
                                                                                     └──► DJI Dock (προσομοίωση στη v1)
```

## Τι περιέχει

| Φάκελος | Τι είναι |
|---|---|
| `server/` | Κεντρικός server και οθόνη ελεγκτή. Python 3, χωρίς εξωτερικά πακέτα, βάση SQLite. |
| `edge/` | Πρόγραμμα για το κουτί σε κάθε επιχείρηση (Raspberry Pi / Linux), με εγκατάσταση ως υπηρεσία. |
| `postman/` | Έτοιμα αιτήματα για δοκιμές και εντολές. |
| `data/` | Δημιουργείται στην πρώτη εκκίνηση: βάση, εικόνες, `credentials.txt`. |

## Γρήγορη εκκίνηση (Windows)

1. Διπλό κλικ στο `start.bat`, ή:
   ```
   python server\app.py --port 8080
   ```
2. Ανοίγει το `http://localhost:8080/`.
3. Στην πρώτη εκκίνηση φτιάχνονται χρήστες με τυχαίους κωδικούς στο **`data/credentials.txt`**:
   - `admin`: διαχειριστής
   - `operator`: ελεγκτής
   - `pelatis`: πελάτης, βλέπει μόνο τη δική του επιχείρηση
4. Πατήστε **«+ Δοκιμαστικός συναγερμός»** πάνω δεξιά για να δείτε όλη τη ροή χωρίς κάμερες.

Υπάρχουν έτοιμα **δείγματα επίδειξης**: 3 επιχειρήσεις στην Αττική με κάμερες, επαφές και 3 σταθμούς drone (προσομοίωση). Αλλάζουν ή διαγράφονται από τη Διαχείριση.

Για γρήγορη προσομοίωση πτήσης: `set SIM_SPEED=5` πριν την εκκίνηση (5 φορές πιο γρήγορα).

## Linux server / Docker

```
docker build -t cam2drone .
docker run -d -p 8080:8080 -v cam2drone-data:/data --name cam2drone cam2drone
```
Σε παραγωγή, ο server μπαίνει πίσω από reverse proxy με HTTPS (π.χ. Caddy ή Nginx), ώστε τα κουτιά να συνδέονται με `https://`.

## Οθόνη ελεγκτή: όλα σε μία οθόνη
- **Αριστερά, ουρά περιστατικών:** ταξινόμηση κατά προτεραιότητα, χρονόμετρο, φίλτρα (ανοιχτά, υψηλή προτεραιότητα, drone, κλειστά, ανά επιχείρηση), ήχος για νέο συναγερμό.
- **Κέντρο:** εικόνα κάμερας (με όλες τις λήψεις του περιστατικού), οθόνη drone με ενδείξεις (φάση, ύψος, μπαταρία, θέση) και χάρτης με επιχειρήσεις, σταθμούς, ακτίνα κάλυψης και θέση του drone.
- **Δεξιά, περιστατικό:**
  - Ανάληψη, Ψευδής, Αποστολή drone, Παύση κάμερας, Κλείσιμο.
  - Σχέδιο ενεργειών (checklist ανά επιχείρηση).
  - Μεγάφωνο drone: έτοιμα μηνύματα, ελεύθερο κείμενο, και κουμπί που κρατάς πατημένο για να μιλήσεις από το μικρόφωνο.
  - Ειδοποιήσεις: SMS, email, κλήση, αστυνομία 100/112 με έτοιμη περίληψη.
  - Χρονολόγιο και αναφορά για εκτύπωση ή PDF.
- **Κλιμάκωση:** αν δεν γίνει ανάληψη μέσα στον χρόνο που έχει οριστεί για την επιχείρηση, το περιστατικό ανεβαίνει προτεραιότητα και ειδοποιείται ο ελεγκτής.

## Πώς χωρίζονται και φιλτράρονται τα σήματα
- **Ανά οργανισμό:** κάθε κουτί έχει δικό του token. Κάθε επιχείρηση έχει και δικό της webhook URL για κάμερες που στέλνουν απευθείας.
- **Φίλτρα:** ωράριο οπλισμού, επιτρεπτοί τύποι συναγερμού, παύση κάμερας, απενεργοποίηση κάμερας. Όσα φιλτράρονται φαίνονται στη «Καταγραφή σημάτων».
- **Συγχώνευση:** σήματα της ίδιας επιχείρησης μέσα σε 2 λεπτά ενώνονται σε ένα περιστατικό.
- **Τύποι:**

  | Τύπος | Προτεραιότητα |
  |---|---|
  | Άτομο, Όχημα, Είσοδος συναγερμού | υψηλή |
  | Ζώνη, Γραμμή, Παραποίηση, Πρόσωπο | μεσαία |
  | Κίνηση | χαμηλή |
  | Απώλεια εικόνας | τεχνικό |

  Η αναγνώριση ατόμου ή οχήματος γίνεται στην ίδια την κάμερα (π.χ. AcuSense, WizSense). Το σύστημα τη διαβάζει και την αξιοποιεί.

## Κουτί (edge) σε Raspberry Pi / Linux
```
scp -r edge pi@<ip-κουτιού>:~
ssh pi@<ip-κουτιού>
cd edge && sudo ./install.sh
sudo nano /opt/cam2drone-edge/config.json      # server, token, κάμερες
/opt/cam2drone-edge/venv/bin/python /opt/cam2drone-edge/agent.py --discover   # βρίσκει ONVIF κάμερες
sudo systemctl start cam2drone-edge && journalctl -u cam2drone-edge -f
```
- Το **token** του κουτιού το παίρνετε από Διαχείριση → Κουτιά → «Νέο κουτί».
- Τύποι πηγών στο `config.json`:

  | Τύπος | Τι κάνει |
  |---|---|
  | `hikvision` | ISAPI alertStream, και για NVR με `channels` |
  | `dahua` | eventManager |
  | `onvif` | PullPoint, χρειάζεται `onvif-zeep` |
  | `webhook` | η κάμερα στέλνει στο κουτί στη θύρα 8090 |
  | `gpio` | ξηρή επαφή, π.χ. έξοδος πίνακα συναγερμού |

- Τραβάει φωτογραφία από την κάμερα σε κάθε συναγερμό.
- Αν πέσει το internet, κρατά τους συναγερμούς και τους στέλνει όταν επανέλθει.
- Κάθε 30″ στέλνει «είμαι ζωντανό» για κάθε κάμερα.
- Ελέγχει ότι η ώρα του είναι σωστή, γιατί το ONVIF το απαιτεί.
- Κάνει μόνο εξερχόμενες συνδέσεις, άρα δεν ανοίγουν θύρες στο router της επιχείρησης.
- Δοκιμή: `agent.py --config config.json --test` στέλνει έναν δοκιμαστικό συναγερμό για κάθε κάμερα.

## Κάμερες χωρίς κουτί (απευθείας webhook)
Από Διαχείριση → Οργανισμοί, αντιγράψτε το «Webhook για κάμερες» της επιχείρησης.
Για Hikvision: Configuration → Network → Advanced → **HTTP Listening** (IP/θύρα του server, URL `/webhook/<token>`), και στο event **Linkage → Notify Surveillance Center**.

## Ειδοποιήσεις
Διαχείριση → Ειδοποιήσεις:
- **SMS:** μέσω HTTP API παρόχου (URL, headers, σώμα JSON με `{to}`, `{text}`, `{sender}`). Στην Ελλάδα το όνομα αποστολέα θέλει προεγγραφή στον πάροχο.
- **Email:** μέσω SMTP.
- Χωρίς ρυθμισμένο πάροχο, οι ειδοποιήσεις **καταγράφονται ως προσομοίωση** και δεν στέλνονται.
- Κλήσεις και αστυνομία: τις κάνει ο ελεγκτής από τηλέφωνο, και το σύστημα δίνει τον αριθμό, την έτοιμη περίληψη και καταγράφει το αποτέλεσμα.

## Drone
Στη v1 οι σταθμοί είναι **προσομοίωση**: απογείωση, πορεία, άφιξη, επιστροφή, μπαταρία, προβολέας, κάμερες, μεγάφωνο.
Η σύνδεση με πραγματικό **DJI Dock 3** γίνεται μέσω **DJI Cloud API**, στην κλάση `DjiCloudAdapter` στο `server/logic.py`. Εκεί είναι γραμμένη η αντιστοίχιση κάθε λειτουργίας:

| Λειτουργία | Εντολή DJI Cloud API |
|---|---|
| Πτήση στο σημείο | `fly_to_point` / wayline |
| Επιστροφή | `return_home` |
| Μεγάφωνο | `drc_speaker_tts_play_start` και ζωντανή μετάδοση (AS1) |
| Προβολέας | AL1 |
| Live εικόνα | `live_start_push` |

Χρειάζεται πραγματικό Dock και λογαριασμός DJI developer.

## API για Postman
- Εισάγετε το `postman/Cam-to-Drone.postman_collection.json` και βάλτε στη μεταβλητή `api_token` το token από το `data/credentials.txt`.
- Header: `Authorization: Bearer <api_token>`.
- Εντολές (`POST /api/command`): `ping`, `demo_alarm`, `ack`, `dispatch_drone`, `speaker`, `light_on`, `light_off`, `return_home`, `note`, `false_alarm`, `close`.
- Χωρίς `incident_id`, η εντολή πάει στο πιο επείγον ανοιχτό περιστατικό.

## Τι μένει για την επόμενη έκδοση
- Πραγματική σύνδεση DJI Dock (Cloud API, MQTT) και live βίντεο μέσω media server (π.χ. MediaMTX).
- Live βίντεο και κλιπ πριν και μετά τον συναγερμό από τις κάμερες (RTSP μέσω του κουτιού).
- PostgreSQL και πολλαπλοί servers για μεγάλο αριθμό πελατών.
- Εφαρμογή κινητού για πελάτες και ειδοποιήσεις push.
- Έλεγχος από νομικό: άδεια ιδιωτικής ασφάλειας (Ν. 2518/1997), άδεια πτήσεων από την ΥΠΑ (BVLOS, κατηγορία Specific), GDPR και ΑΠΔΠΧ, πρότυπο EN 50518.
